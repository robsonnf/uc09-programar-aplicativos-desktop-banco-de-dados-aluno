Guia de consultas SQL

Os comandos do MySQL que você usa na UC, cada um com a forma geral, um exemplo no banco dos kits e a tela real do cliente mysql.

Use este guia para consultar um comando quando precisar, não para ler de uma vez. Cada tópico traz a forma geral do comando, um exemplo rodado no cliente mysql com os dados fictícios do guia e a resposta que o servidor deu de verdade. No fim de cada tópico, "Visto em" leva à aula onde o comando foi ensinado ou onde ele vai ser usado.

Os exemplos rodam no banco kits_teste, com o usuário kits_app criado na A08. Nunca rode o guia.sql no banco kits: ele apaga e recria as tabelas. Os testes do projeto recriam o kits_teste sozinhos, então você pode usar esse banco à vontade.

Os tempos entre parênteses, como (0.00 sec), e o número da conexão mudam a cada execução. O resto da tela deve sair igual no seu computador. Se sair diferente, confira se o guia.sql foi carregado por último.

Antes de começar

Os dados do guia são quatro kits e nove itens. O kit Oficina Montagem não tem nenhum item, e o Teclado está com quantidade zero: esses dois casos aparecem em vários tópicos, porque é neles que as consultas costumam errar.

Carregar os dados do guia

Salve o conteúdo acima como guia.sql na pasta onde você abre o terminal. Entre no kits_teste e carregue o arquivo com SOURCE. As tabelas são as mesmas do projeto (kit, item e movimentacao), sem a importacao da A19.

-- guia.sql: dados fictícios do Guia de consultas. Rode só no kits_teste: apaga e recria as tabelas.
DROP TABLE IF EXISTS emprestimo, importacao, movimentacao, item, kit;

CREATE TABLE kit (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(80) NOT NULL
);

CREATE TABLE item (
  id INT AUTO_INCREMENT PRIMARY KEY,
  kit_id INT NOT NULL,
  nome VARCHAR(80) NOT NULL,
  quantidade INT NOT NULL,
  CONSTRAINT quantidade_nao_negativa CHECK (quantidade >= 0),
  CONSTRAINT item_kit FOREIGN KEY (kit_id) REFERENCES kit(id)
);

CREATE TABLE movimentacao (
  id INT AUTO_INCREMENT PRIMARY KEY,
  origem_id INT NOT NULL,
  destino_id INT NOT NULL,
  quantidade INT NOT NULL,
  momento TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT movimentacao_positiva CHECK (quantidade > 0)
);

INSERT INTO kit (id, nome) VALUES
  (1, 'Treinamento Redes'), (2, 'Treinamento Suporte'), (3, 'Oficina Montagem'), (4, 'Oficina Arduino');

INSERT INTO item (id, kit_id, nome, quantidade) VALUES
  (1, 1, 'Cabo', 3), (2, 1, 'Notebook', 2), (3, 2, 'Cabo', 5), (4, 1, 'Switch', 1), (5, 2, 'Mouse', 8),
  (6, 2, 'Teclado', 0), (7, 4, 'Placa', 6), (8, 4, 'Protoboard', 10), (9, 4, 'Jumper', 40);

INSERT INTO movimentacao (origem_id, destino_id, quantidade, momento) VALUES
  (3, 1, 2, '2026-11-03 09:15:00'), (8, 2, 1, '2026-11-04 14:30:00'), (3, 1, 1, '2026-11-10 10:00:00');

Ler dados

SELECT escolhe as colunas, FROM diz de qual tabela, WHERE filtra as linhas e ORDER BY põe em ordem. É nessa ordem que se escreve; a cláusula LIMIT vem sempre por último.

SELECT: escolher colunas

Liste só as colunas de que você precisa. Sem ORDER BY, o MySQL não promete nenhuma ordem: aqui as linhas saíram na ordem do id, mas não conte com isso no aplicativo.

SELECT coluna1, coluna2 FROM tabela;

Visto em: A06, A08

SELECT *: todas as colunas

O asterisco traz todas as colunas. Serve para olhar uma tabela no terminal; no código do aplicativo, nomeie as colunas, para uma coluna nova na tabela não mudar o que a consulta devolve.

SELECT * FROM tabela;

Visto em: A07

AS: apelidos de coluna

AS dá outro nome à coluna no resultado, sem mudar a tabela. Os apelidos ficam ainda mais úteis com funções, como COUNT(*) AS itens, e com JOIN, para apelidar tabelas.

SELECT coluna AS apelido FROM tabela;

Visto em: A08, A17

DISTINCT: sem repetições

Os kits 1 e 2 têm seis itens, mas Cabo aparece nos dois. DISTINCT junta as linhas iguais, e o resultado tem cinco nomes. Ele compara a linha inteira do resultado: com duas colunas, só some o que for igual nas duas.

SELECT DISTINCT coluna FROM tabela;

Visto em: A24

WHERE: filtrar linhas

A condição compara colunas com valores. Os operadores são =, <> (diferente), <, <=, > e >=. Repare que >= 6 inclui a Placa, que tem exatamente 6.

SELECT colunas FROM tabela WHERE condição;

Visto em: A06, A08

AND, OR e NOT

AND exige as duas condições; OR aceita qualquer uma; NOT inverte. AND é avaliado antes de OR, por isso os parênteses na segunda consulta: sem eles, o NOT kit_id = 4 valeria só para o Cabo, e um item esgotado do kit 4 também entraria no resultado.

WHERE condição1 AND (condição2 OR condição3)
WHERE NOT condição

Visto em: A06, A09, A16

ORDER BY: pôr em ordem

DESC ordena do maior para o menor; sem nada, a ordem é crescente (ASC). A segunda coluna só decide quando a primeira empata; aqui nenhuma quantidade se repete, então o nome não chegou a ser usado. Os dois Cabo saíram separados porque têm quantidades diferentes.

SELECT colunas FROM tabela ORDER BY coluna1 DESC, coluna2;

Visto em: A16

LIMIT e OFFSET: só algumas linhas

LIMIT 3 traz as três primeiras linhas; OFFSET 3 pula as três primeiras, que é como se faz a segunda página de uma lista. Use LIMIT sempre com ORDER BY, e com um desempate que não se repete (o id), ou a página muda de uma execução para outra.

SELECT colunas FROM tabela ORDER BY coluna LIMIT quantas OFFSET pular;

Visto em: A16, A19

Filtrar com mais precisão

Estes operadores encurtam condições que, escritas com AND e OR, ficariam longas e fáceis de errar.

IN: um valor de uma lista

IN equivale a vários OR seguidos. Monitor não existe nos dados e não causa erro: só não traz linha.

WHERE coluna IN (valor1, valor2, valor3)

Visto em: A10, A24

BETWEEN: dentro de uma faixa

BETWEEN inclui as duas pontas: o 2 e o 6 entraram. Com datas, cuidado: '2026-11-05' quer dizer meia-noite do dia 5, então uma movimentação às 10h do dia 5 ficaria de fora.

WHERE coluna BETWEEN mínimo AND máximo

Visto em: A24

LIKE: procurar por trecho

% vale qualquer quantidade de caracteres, inclusive nenhuma; _ vale exatamente um. Para procurar um % ou um _ de verdade, é preciso escapar o caractere, como a A16 faz na busca da janela.

WHERE coluna LIKE 'P%'    -- % é qualquer sequência
WHERE coluna LIKE '_abo'  -- _ é exatamente um caractere

Visto em: A08, A16

IS NULL: o valor que falta

NULL quer dizer "não há valor". Ele aparece, por exemplo, nas colunas do item quando o LEFT JOIN não acha nenhum item para o kit. Qualquer comparação com NULL usando = dá desconhecido, nem verdadeiro nem falso: por isso a segunda consulta contou zero linhas. Use sempre IS NULL.

WHERE coluna IS NULL
WHERE coluna IS NOT NULL

Visto em: A17, A24

Contar, somar e agrupar

As funções de agregação resumem muitas linhas num número. Com GROUP BY, o resumo sai por grupo, por exemplo um total para cada kit.

COUNT: quantas linhas

COUNT(*) conta linhas. COUNT(DISTINCT coluna) conta valores diferentes: são 9 itens, mas só 8 nomes, porque Cabo se repete, e só 3 kits têm itens.

SELECT COUNT(*) FROM tabela;
SELECT COUNT(DISTINCT coluna) FROM tabela;

Visto em: A16, A17

SUM e AVG: total e média

SUM soma e AVG calcula a média. A média de números inteiros sai com casas decimais (75 / 9 = 8,3333). No Python, o conector entrega esses valores como Decimal, como a A17 mostrou.

SELECT SUM(coluna), AVG(coluna) FROM tabela;

Visto em: A17, A24

MIN e MAX: menor e maior

O WHERE filtra antes de agregar: aqui só os itens do kit 1 entraram na conta.

SELECT MIN(coluna), MAX(coluna) FROM tabela WHERE condição;

Visto em: A17, A24

GROUP BY: um resumo por grupo

Cada valor diferente de kit_id vira uma linha do resultado. Toda coluna do SELECT que não está numa função precisa estar no GROUP BY; senão o MySQL recusa a consulta (erro 1055, visto na A17). O kit 3 não aparece porque não tem itens: para ele aparecer, é preciso partir do kit com LEFT JOIN.

SELECT coluna, COUNT(*), SUM(outra) FROM tabela GROUP BY coluna;

Visto em: A17

HAVING: filtrar grupos

WHERE filtra linhas antes de agrupar; HAVING filtra os grupos depois. Uma condição sobre o total do kit só pode ir no HAVING, porque o total só existe depois do GROUP BY.

SELECT coluna, SUM(outra) FROM tabela GROUP BY coluna HAVING SUM(outra) > valor;

Visto em: A17

Juntar tabelas

O JOIN liga as linhas de duas tabelas pela condição do ON, quase sempre a chave estrangeira com a chave primária. Apelide as tabelas (item AS i, kit AS k) para a consulta caber na linha.

JOIN (INNER JOIN): só o que tem par

Cada item aparece junto com o nome do seu kit. Um kit sem item não tem par e fica de fora. Escrever INNER JOIN ou só JOIN dá no mesmo.

SELECT a.coluna, b.coluna FROM a JOIN b ON b.id = a.b_id;

Visto em: A06, A08, A17

LEFT JOIN: todos da esquerda

Todos os kits aparecem, inclusive a Oficina Montagem, que não tem itens. Nela as colunas do item vêm NULL, e COUNT(i.id) conta zero, porque COUNT de uma coluna não conta NULL. Com COUNT(*), o kit vazio apareceria com 1, o erro que a A17 investiga.

SELECT a.coluna, COUNT(b.id) FROM a LEFT JOIN b ON b.a_id = a.id GROUP BY a.id, a.coluna;

Visto em: A06, A17

RIGHT JOIN: todos da direita

É o LEFT JOIN visto do outro lado: guarda todas as linhas da tabela da direita. Dá o mesmo resultado que trocar as tabelas de lugar e usar LEFT JOIN, que é a forma mais comum e mais fácil de ler.

SELECT a.coluna, b.coluna FROM a RIGHT JOIN b ON b.id = a.b_id;

Visto em: A24

CROSS JOIN: todas as combinações

CROSS JOIN junta cada linha de uma tabela com cada linha da outra: 4 kits × 9 itens = 36 linhas. É o que acontece por engano num JOIN sem a condição certa no ON. Com a condição, voltam as 9 linhas de verdade.

SELECT ... FROM a CROSS JOIN b;

Visto em: A17, A24

Autojunção: a tabela com ela mesma

A mesma tabela entra duas vezes, com apelidos diferentes. Aqui ela acha itens de mesmo nome em kits diferentes. O a.id < b.id evita comparar um item com ele mesmo e mostrar o mesmo par duas vezes.

SELECT a.coluna, b.coluna FROM t AS a JOIN t AS b ON a.coluna = b.coluna AND a.id < b.id;

Visto em: A24

Combinar consultas e decidir na consulta

Uma consulta pode usar o resultado de outra, juntar dois resultados ou calcular um valor diferente para cada linha.

UNION e UNION ALL: um resultado embaixo do outro

UNION põe o segundo resultado embaixo do primeiro e tira as repetições; UNION ALL mantém todas as linhas. Os dois SELECT precisam ter o mesmo número de colunas, e o nome da coluna vem do primeiro.

SELECT coluna FROM a UNION SELECT coluna FROM b;

Visto em: A25

Subconsulta: uma consulta dentro da outra

A consulta entre parênteses roda e devolve um valor, a média 8,3333, que a de fora usa no WHERE. Só a Protoboard e o Jumper estão acima da média.

WHERE coluna > (SELECT AVG(coluna) FROM tabela)

Visto em: A25

EXISTS e NOT EXISTS: existe alguma linha?

EXISTS é verdadeiro quando a subconsulta acha pelo menos uma linha; o que ela seleciona não importa, por isso o SELECT 1. A primeira consulta acha o kit com item esgotado; a segunda, o kit sem nenhum item.

WHERE EXISTS (SELECT 1 FROM outra WHERE outra.a_id = a.id AND condição)

Visto em: A25

ANY e ALL: comparar com uma lista

> ALL exige ser maior que todos os valores da lista (os do kit 2 são 5, 8 e 0, então precisa passar de 8). < ANY basta ser menor que algum deles: todos os itens do kit 1 são menores que 8.

WHERE coluna > ALL (SELECT ...)
WHERE coluna < ANY (SELECT ...)

Visto em: A25

CASE: um valor conforme a condição

CASE testa as condições na ordem e para na primeira verdadeira. Por isso o zero vira "esgotado" e não "baixo", embora 0 também seja menor que 3.

CASE WHEN condição1 THEN valor1 WHEN condição2 THEN valor2 ELSE outro END

Visto em: A25

COALESCE e IFNULL: trocar NULL por um valor

SUM de nenhuma linha dá NULL, não zero, como se vê no kit sem itens. COALESCE devolve o primeiro valor que não é NULL; IFNULL faz o mesmo com dois valores. O resumo da A17 usa COALESCE para o kit vazio mostrar 0.

COALESCE(expressão, valor_se_for_null)
IFNULL(expressão, valor_se_for_null)

Visto em: A17

Incluir, alterar e remover

Os exemplos desta parte abrem uma transação com START TRANSACTION e terminam com ROLLBACK, que desfaz tudo. Assim os dados do guia continuam iguais para os outros tópicos. No aplicativo, quem confirma é o COMMIT, como na A10.

INSERT INTO: incluir linhas

Um INSERT pode incluir várias linhas de uma vez. O id veio do AUTO_INCREMENT (10 e 11). Depois do ROLLBACK, os itens sumiram; no código Python os valores vão por parâmetro, nunca colados no texto do SQL.

INSERT INTO tabela (coluna1, coluna2) VALUES (valor1, valor2), (valor3, valor4);

Visto em: A06, A08, A10

INSERT ... SELECT: incluir a partir de uma consulta

No lugar de VALUES vai uma consulta, e cada linha do resultado vira uma linha nova. Aqui o kit 3 recebeu uma unidade de cada item do kit 4. Os ids começam em 12: o ROLLBACK do tópico anterior não devolveu o 10 e o 11.

INSERT INTO tabela (colunas) SELECT valores FROM outra WHERE condição;

Visto em: A24

UPDATE: alterar linhas

A conta dentro do SET (quantidade - 1) usa o valor que está no banco naquele momento, por isso duas retiradas ao mesmo tempo não se perdem. A condição quantidade >= 1 recusa a retirada do Teclado: Rows matched: 0 avisa que nada foi alterado.

UPDATE tabela SET coluna = novo_valor WHERE condição;

Visto em: A09, A10

DELETE FROM: remover linhas

Remova pelo id, como na A09. O kit 1 ainda tem itens, e a chave estrangeira item_kit recusa a remoção (erro 1451): o banco não deixa sobrar item órfão.

DELETE FROM tabela WHERE condição;

Visto em: A09, A13

Criar e mudar a estrutura

Estes comandos mudam as tabelas, não os dados. No MySQL eles confirmam sozinhos (commit implícito, A10): um ROLLBACK depois não desfaz um CREATE TABLE. A tabela emprestimo destes exemplos é só do guia e é apagada no fim.

CREATE TABLE e as restrições

PRIMARY KEY identifica a linha, e AUTO_INCREMENT numera sozinho. NOT NULL exige um valor; NULL o deixa opcional, como a devolução que ainda não aconteceu. DEFAULT dá o valor quando o INSERT não informa a coluna. FOREIGN KEY e CHECK são as regras que o banco garante. DESCRIBE mostra como a tabela ficou.

CREATE TABLE tabela (
  id INT AUTO_INCREMENT PRIMARY KEY,
  coluna TIPO NOT NULL DEFAULT valor,
  CONSTRAINT nome FOREIGN KEY (coluna) REFERENCES outra(id),
  CONSTRAINT nome CHECK (condição)
);

Visto em: A06, A08, A09

As restrições recusando dados

Item 99 não existe (chave estrangeira, erro 1452); quantidade 0 não passa no CHECK (erro 3819); sem técnico, o NOT NULL sem DEFAULT recusa (erro 1364). No Python, esses erros chegam como exceções do conector, e o aplicativo traduz cada uma numa mensagem para quem usa.

-- cada regra recusa o INSERT com um erro e um número

Visto em: A06, A08, A10

Datas: DATE, DATE_FORMAT e DATEDIFF

DATE guarda o dia e TIMESTAMP, o dia com a hora. Digite as datas no formato 'AAAA-MM-DD'; DATE_FORMAT mostra no formato brasileiro. DATEDIFF conta os dias entre duas datas e dá NULL quando falta uma delas, como no empréstimo ainda não devolvido.

DATE_FORMAT(data, '%d/%m/%Y')
DATEDIFF(data_final, data_inicial)

Visto em: A10, A24

ALTER TABLE: mudar uma tabela que já tem dados

Uma coluna nova em tabela com dados precisa aceitar NULL ou ter DEFAULT, senão as linhas que já existem ficariam sem valor. Mudanças assim no projeto vão para um arquivo de migração, como na A09.

ALTER TABLE tabela ADD COLUMN coluna TIPO NULL;
ALTER TABLE tabela DROP COLUMN coluna;

Visto em: A09, A10

DROP TABLE: apagar a tabela

DROP TABLE apaga a tabela com todos os dados, sem pedir confirmação. Rodar de novo dá erro 1051, porque ela já não existe; IF EXISTS troca o erro por um aviso, por isso os scripts de esquema começam com ele.

DROP TABLE tabela;
DROP TABLE IF EXISTS tabela;

Visto em: A08, A09

SHOW DATABASES e CREATE DATABASE

O kits_app só enxerga os bancos em que tem permissão e não pode criar outros (erro 1044). Isso é de propósito: o aplicativo não precisa criar bancos, então o usuário dele não pode. Os bancos kits e kits_teste foram criados com o root na A08.

SHOW DATABASES;
CREATE DATABASE nome;    -- só com o root
DROP DATABASE nome;      -- só com o root

Visto em: A08

Índices e visões

Um índice deixa a busca mais rápida; uma visão guarda uma consulta com nome. Os dois ficam para quando o projeto precisar deles, e a A25 discute quando vale a pena.

CREATE INDEX e EXPLAIN

EXPLAIN mostra como o MySQL vai buscar, sem rodar a consulta. Sem índice, type ALL quer dizer ler a tabela inteira (9 linhas). Com o índice em nome, type ref e key item_nome: ele vai direto às 2 linhas de Cabo. ANALYZE TABLE atualiza as estatísticas que o EXPLAIN usa. O \G no lugar do ponto e vírgula mostra uma coluna por linha, o que ajuda quando a tabela do resultado é larga.

EXPLAIN SELECT ...;
CREATE INDEX nome ON tabela (coluna);
DROP INDEX nome ON tabela;

Visto em: A25

CREATE VIEW: uma consulta com nome

A visão não guarda dados: cada SELECT nela roda a consulta de novo, com os dados do momento. Ela se consulta como uma tabela, inclusive com WHERE.

CREATE VIEW nome AS SELECT ...;
SELECT * FROM nome;
DROP VIEW nome;

Visto em: A25

Do terminal ao Python

No aplicativo, os valores nunca entram colados no texto do SQL. O próprio MySQL tem uma forma de separar o comando dos valores, e é o mesmo que o conector faz quando você usa %s.

Parâmetros: o comando separado dos valores

PREPARE guarda o comando com ? no lugar dos valores, e EXECUTE ... USING envia os valores à parte. Um apóstrofo no valor não quebra o comando nem muda o que ele faz. No Python, o %s do mysql.connector cumpre o mesmo papel: os valores vão na tupla, nunca numa f-string.

cursor.execute(
    'SELECT nome, quantidade FROM item WHERE kit_id = %s AND nome LIKE %s',
    (kit_id, trecho + '%'))
