Um kit e os seus itens ↗

A chave estrangeira item.kit_id já liga cada item ao seu kit no banco. O relationship leva essa ligação para as classes: KitBanco ganha itens, a lista dos ItemBanco do kit, e ItemBanco ganha kit, o KitBanco do item. O tipo diz o formato: Mapped[list['ItemBanco']] é uma lista; Mapped[KitBanco], um objeto só. back_populates diz que os dois atributos são a mesma ligação vista de cada lado, e a sessão mantém os dois de acordo.

O relacionamento não cria coluna nenhuma: o teste do mapeamento da A23 continua passando sem mudar. O que muda é o que o ORM escreve por você: o join pelo relacionamento (select(...).join(ItemBanco.kit)) já leva a condição do ON, e ler kit.itens manda um SELECT dos itens daquele kit.

Esse SELECT sai na hora em que você lê o atributo, e não antes: é o carregamento preguiçoso (lazy loading). Por isso a sessão precisa estar aberta. Fora do with, ler kit.itens de um objeto que ainda não carregou os itens dá DetachedInstanceError. É um dos motivos de o repositório devolver tuplas para a janela, e não objetos do ORM.

Quem decide o que acontece com os itens ↗

Sem nenhuma opção, ao apagar um kit, o SQLAlchemy carrega os itens dele e troca o kit_id de cada um por NULL antes do DELETE. O passo 3 do tutorial mostra esse UPDATE. Como kit_id é NOT NULL, o banco recusa, mas com o erro 1048 (coluna não pode ser nula), e não com o 1451 que a A14 traduz em KitComItens.

Com cascade='all, delete-orphan', o ORM vai além: apaga os itens e depois o kit, e o banco não tem nada a recusar. É o relato 1 da partida. Serve para dados que só existem dentro do pai; nos kits, apagar o estoque sem perguntar é perder registro.

O projeto usa passive_deletes='all': o ORM não toca nos itens, e quem decide é a chave estrangeira do esquema.sql, como no SQL direto. O remover_kit chama sessao.flush() dentro do try, para o erro 1451 aparecer ali e virar KitComItens. Sem o flush, o DELETE só sairia no fim do em_sessao, fora do repositório, e a janela receberia um erro que não sabe mostrar.

As consultas da janela com o ORM ↗

Cada consulta do SQL direto tem a sua forma no ORM, e o Guia de consultas mostra cada comando no cliente mysql. outerjoin(KitBanco.itens) é o LEFT JOIN; func.count(ItemBanco.id), func.sum, func.min, func.max, func.avg e func.coalesce são as funções do SQL; group_by e order_by são as cláusulas. ItemBanco.id.is_(None) vira IS NULL; quantidade.between(2, 5), BETWEEN com as duas pontas; nome.in_(nomes), IN; .distinct(), DISTINCT.

As regras da A16 continuam: o trecho da busca vai com escapar_like e escape='\\', senão _ e % viram curingas. A coluna da ordem sai de um dicionário com as colunas permitidas (COLUNAS, com as mesmas chaves do ORDENS do SQL), nunca de getattr(ItemBanco, ordem) com o texto que veio da janela: assim, ordem='kit_id' é recusada.

Os números chegam como no SQL direto: SUM e AVG voltam como Decimal pelo conector. O resumo devolve int(unidades), e as estatísticas arredondam a média a uma casa, como float. As exceções (KitComItens, ItemMudou) e o escape do LIKE vêm do kits/repositorio.py: o serviço de dados recebe os mesmos erros dos dois repositórios.

Uma consulta por kit: o problema N+1 ↗

Um relatório que percorre os kits e lê kit.itens de cada um faz 1 SELECT para os kits e mais 1 por kit, na hora em que cada lista é lida. Com 3 kits são 4 consultas; com 40, 41. Cada uma é rápida, mas todas juntas deixam a tela lenta, e o código não mostra isso: só o SQL gerado mostra.

selectinload(KitBanco.itens), nas options da consulta, traz os itens de todos os kits numa segunda consulta só, com WHERE kit_id IN (...). São 2 consultas, sejam quantos forem os kits. joinedload faz o mesmo com um JOIN numa consulta só, repetindo os dados do kit em cada linha. Nas listas de um para muitos, a documentação recomenda o selectinload.

Para provar, o teste conta os SELECT com o mesmo evento before_cursor_execute do tutorial e cria mais kits: se a contagem crescer com o número de kits, é N+1.

def criar_motor(config=None):
    """O motor (Engine) a partir do banco.ini, como o conexao_banco da A08. URL.create monta o endereço com
    cada parte no seu lugar: uma senha com @ ou : não quebra nada. O motor guarda um conjunto de conexões
    abertas (pool) e as empresta a cada sessão; pool_pre_ping confere se a emprestada ainda está viva."""
    cfg = config or ler_config()
    url = URL.create('mysql+mysqlconnector', username=cfg['user'], password=cfg['password'], host=cfg['host'],
                     port=cfg['port'], database=cfg['database'])
    return create_engine(url, pool_pre_ping=True)


def em_sessao(operacao, motor):
    """Roda operacao(sessao) numa transação: confirma no fim, desfaz tudo se algo der errado.
    É o em_transacao da A10, para o ORM; a sessão fecha e devolve a conexão ao motor."""
    with Session(motor) as sessao, sessao.begin():
        return operacao(sessao)

from kits.orm import ItemBanco, KitBanco

def listar_kits(sessao):
    return [tuple(linha) for linha in sessao.execute(select(KitBanco.id, KitBanco.nome).order_by(KitBanco.nome, KitBanco.id))]


def criar_kit(sessao, nome):
    kit = Kit(nome)
    outro = sessao.scalar(select(KitBanco.nome).where(KitBanco.nome == kit.nome))
    if outro is not None:
        raise ValueError(f'Já existe o kit {outro}')
    novo = KitBanco(nome=kit.nome)
    sessao.add(novo)
    sessao.flush()
    return novo.id


def adicionar_item(sessao, kit_id, item):
    existente = sessao.scalar(select(ItemBanco).where(ItemBanco.kit_id == kit_id, ItemBanco.nome == item.nome)
                              .with_for_update())
    if existente is not None:
        existente.quantidade += item.quantidade
        return existente.id
    novo = ItemBanco(kit_id=kit_id, nome=item.nome, quantidade=item.quantidade)
    sessao.add(novo)
    try:
        sessao.flush()
    except exc.IntegrityError as erro:
        if getattr(erro.orig, 'errno', None) == SEM_KIT:
            raise LookupError(f'Kit {kit_id} não existe') from erro
        raise
    return novo.id


def remover_item(sessao, item_id):
    item = sessao.get(ItemBanco, item_id)
    if item is None:
        raise LookupError(f'Item {item_id} não existe')
    sessao.delete(item)


def consultar_itens(sessao, kit_id, trecho='', ordem='nome', descendente=False):
    if ordem not in COLUNAS:
        raise ValueError(f'Ordem desconhecida: {ordem}')
    coluna = COLUNAS[ordem].desc() if descendente else COLUNAS[ordem]
    consulta = (select(ItemBanco.id, ItemBanco.nome, ItemBanco.quantidade)
                .where(ItemBanco.kit_id == kit_id, ItemBanco.nome.like(f'%{trecho.strip()}%'))
                .order_by(coluna, ItemBanco.id))
    return [tuple(linha) for linha in sessao.execute(consulta)]


def editar_item(sessao, item_id, antes, depois):
    item = sessao.get(ItemBanco, item_id, with_for_update=True)
    if item is None:
        raise LookupError(f'Item {item_id} não existe')
    if (item.nome, item.quantidade) != (antes.nome, antes.quantidade):
        raise ItemMudou(f'{antes.nome} mudou depois que você leu: agora é {item.nome} com {item.quantidade}')
    outro = sessao.scalar(select(ItemBanco.nome).where(ItemBanco.kit_id == item.kit_id, ItemBanco.nome == depois.nome,
                                                       ItemBanco.id != item_id).with_for_update())
    if outro is not None:
        raise ValueError(f'O kit já tem um item {outro}')
    item.nome, item.quantidade = depois.nome, depois.quantidade


def remover_kit(sessao, kit_id):
    kit = sessao.get(KitBanco, kit_id)
    if kit is None:
        raise LookupError(f'Kit {kit_id} não existe')
    for item in kit.itens:
        sessao.delete(item)
    sessao.delete(kit)


def resumo_kits(sessao):
    consulta = (select(KitBanco.id, KitBanco.nome, func.count(ItemBanco.id), func.coalesce(func.sum(ItemBanco.quantidade), 0))
                .join(KitBanco.itens).group_by(KitBanco.id, KitBanco.nome).order_by(KitBanco.nome, KitBanco.id))
    return [(kit_id, nome, itens, int(unidades)) for kit_id, nome, itens, unidades in sessao.execute(consulta)]


def itens_abaixo(sessao, limite):
    consulta = (select(KitBanco.nome, ItemBanco.nome, ItemBanco.quantidade).join(ItemBanco.kit)
                .where(ItemBanco.quantidade < limite).order_by(ItemBanco.quantidade, KitBanco.nome, ItemBanco.nome))
    return [tuple(linha) for linha in sessao.execute(consulta)]


def kits_vazios(sessao):
    consulta = (select(KitBanco.id, KitBanco.nome).outerjoin(KitBanco.itens).where(ItemBanco.id.is_(None))
                .order_by(KitBanco.nome, KitBanco.id))
    return [tuple(linha) for linha in sessao.execute(consulta)]


def itens_entre(sessao, minimo, maximo):
    if minimo > maximo:
        raise ValueError(f'Faixa vazia: {minimo} é maior que {maximo}')
    consulta = (select(KitBanco.nome, ItemBanco.nome, ItemBanco.quantidade).join(ItemBanco.kit)
                .where(ItemBanco.quantidade.between(minimo, maximo)).order_by(ItemBanco.quantidade, KitBanco.nome, ItemBanco.nome))
    return [tuple(linha) for linha in sessao.execute(consulta)]


def nomes_cadastrados(sessao, nomes):
    if not nomes:
        return []
    consulta = select(ItemBanco.nome).where(ItemBanco.nome.in_(nomes)).distinct().order_by(ItemBanco.nome)
    return list(sessao.scalars(consulta))


def estatisticas(sessao):
    consulta = (select(KitBanco.nome, func.count(ItemBanco.id), func.min(ItemBanco.quantidade), func.max(ItemBanco.quantidade),
                       func.avg(ItemBanco.quantidade))
                .join(KitBanco.itens).group_by(KitBanco.id, KitBanco.nome).order_by(KitBanco.nome, KitBanco.id))
    return [(nome, itens, menor, maior, round(float(media), 1)) for nome, itens, menor, maior, media in sessao.execute(consulta)]


def relatorio_kits(sessao):
    kits = sessao.scalars(select(KitBanco).order_by(KitBanco.nome, KitBanco.id))
    return [(kit.nome, [(item.nome, item.quantidade) for item in kit.itens]) for kit in kits]
