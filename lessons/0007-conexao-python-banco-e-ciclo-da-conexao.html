O suporte rodou um script de cadastro em lote e apareceu no banco um item de um kit que não existe, embora o esquema da A06 recuse isso. Hoje você descobre por quê, entrega o módulo de conexão do projeto e prova com testes que uma falha no meio do lote não deixa nada gravado pela metade.

Nesta aula o Python abre a conexão com o kits.db da A06, sem interface gráfica e sem ORM. Os comandos SQL ainda são fixos no código: consultas com valores vindos do usuário são tema da A08. Use dados fictícios.

O item do kit que não existe ↗

O suporte recebeu um script de um colega para cadastrar um lote de itens. Depois de rodá-lo, a listagem mostrou um Projetor no kit 99. Não existe kit 99, e o esquema que você escreveu na A06 tem REFERENCES kit(id). O script, ainda por cima, liga o PRAGMA das chaves estrangeiras.

O ciclo de uma conexão ↗

  1. Achar o arquivo

    Calcular o caminho de kits.db a partir do projeto, não da pasta em que o terminal está.

  2. Abrir e ligar

    Abrir a conexão e ligar as chaves estrangeiras antes de qualquer comando que altere dados.

  3. Usar

    Executar o lote inteiro dentro de um único bloco.

  4. Gravar ou desfazer

    Sem erro, commit. Com erro, rollback de tudo o que o bloco fez, e o erro segue para quem chamou.

  5. Fechar e provar

    Fechar sempre e conferir o resultado em uma conexão nova.

Abrir a conexão certa, no arquivo certo ↗

O módulo sqlite3 vem com o Python: não há nada para instalar. sqlite3.connect(caminho) abre uma conexão com o arquivo do banco. Se o arquivo não existir, ele cria um banco vazio em silêncio, e o erro só aparece depois, como no such table: item.

Um caminho relativo, como 'kits.db', é procurado na pasta em que o terminal está, e não na pasta do código. Rodar o programa de outra pasta cria um segundo kits.db, vazio. Por isso o módulo calcula o caminho a partir do próprio arquivo, com Path(__file__), e recusa um banco que não existe.

As chaves estrangeiras começam desligadas em cada conexão nova, como você viu na A06. E há um detalhe a mais: PRAGMA foreign_keys = ON não tem efeito se uma transação já estiver aberta. Ligue o PRAGMA logo depois de abrir, antes de qualquer INSERT, UPDATE ou DELETE.

O arquivo fantasma

Se aparecer no such table logo depois de criar o banco, procure um kits.db novo, com 0 bytes, na pasta em que você rodou o comando. O banco de verdade continua intacto; o programa abriu outro.

A transação que você não abriu ↗

No modo padrão do sqlite3, que é o mesmo do Python 3.12 ao 3.14, o primeiro INSERT, UPDATE ou DELETE abre uma transação sem você pedir. Tudo o que vier depois fica pendente até o commit, que grava, ou o rollback, que desfaz. Fechar a conexão sem commit descarta o que estava pendente.

É isso que permite o tudo ou nada: se o lote inteiro estiver em uma transação, um erro no meio desfaz também as linhas que já tinham entrado. O item com kit inexistente é recusado pelo banco; o rollback cuida das outras linhas do mesmo lote.

O que cada comando faz com o que está pendente
ComandoEfeito no que está pendenteConexão depois
commit()GravaContinua aberta
rollback()DesfazContinua aberta
close() sem commitDescartaFechada; qualquer comando dá ProgrammingError
Erro em um INSERTSó aquele comando falha; o que veio antes continua pendenteContinua aberta, esperando commit ou rollback
Não troque o modo nesta aula

O Python 3.12 criou o atributo autocommit, que muda esse comportamento. Nesta aula use o padrão, sem passar autocommit nem isolation_level para connect.

Um bloco with que grava, desfaz e fecha ↗

A conexão do sqlite3 aceita with, mas esse with só faz commit ou rollback: ele não fecha a conexão. Muita gente descobre isso tarde, com o arquivo do banco preso no Windows.

Para ter as três garantias em um lugar só, o projeto ganha um bloco próprio, escrito com contextlib.contextmanager. O código antes do yield prepara; o yield entrega o recurso para quem está no with; o resto do try roda só se o bloco terminou bem; o except roda se houve erro; o finally roda sempre. O exemplo abaixo usa um cronômetro para mostrar a forma, sem banco.

with sqlite3.connect(...)

Grava ou desfaz, mas a conexão continua aberta depois do bloco. O PRAGMA, o caminho e o fechamento ficam por conta de cada script.

with sqlite3.connect('kits.db') as con:
    con.execute(...)
# con ainda está aberta aqui

with conexao_banco()

Um só lugar acha o arquivo, liga o PRAGMA, grava ou desfaz e fecha. Quem usa não precisa lembrar de nada disso.

with conexao_banco() as con:
    con.execute(...)
# gravado ou desfeito, e fechado
Desfazer não é esconder

Depois do rollback, o erro precisa seguir para quem chamou, como na A04. Um bloco que desfaz e não relança faz o lote parecer gravado quando nada foi gravado.

"""Testes do módulo de conexão: cada teste usa um banco novo, criado pelos scripts da A06."""
import sqlite3
import tempfile
import unittest
from pathlib import Path

from kits.banco import abrir, caminho_banco, conexao_banco

RAIZ = Path(__file__).resolve().parent.parent


class TestBanco(unittest.TestCase):
    def setUp(self):
        pasta = tempfile.TemporaryDirectory(ignore_cleanup_errors=True)
        self.addCleanup(pasta.cleanup)
        self.caminho = Path(pasta.name, 'kits.db')
        con = sqlite3.connect(self.caminho)
        for script in ('esquema.sql', 'dados.sql'):
            con.executescript((RAIZ / 'sql' / script).read_text(encoding='utf-8'))
        con.close()

    def contar_itens(self):
        con = sqlite3.connect(self.caminho)
        try:
            return con.execute('SELECT count(*) FROM item').fetchone()[0]
        finally:
            con.close()

    def test_caminho_padrao_fica_na_raiz_do_projeto(self):
        self.assertEqual(caminho_banco(), RAIZ / 'kits.db')

    def test_abrir_liga_as_chaves_estrangeiras(self):
        con = abrir(self.caminho)
        self.addCleanup(con.close)
        self.assertEqual(con.execute('PRAGMA foreign_keys').fetchone(), (1,))

    def test_bloco_grava_quando_termina_bem(self):
        antes = self.contar_itens()
        with conexao_banco(self.caminho) as con:
            con.execute("INSERT INTO item (kit_id, nome, quantidade) VALUES (1, 'Mouse', 2)")
        self.assertEqual(self.contar_itens(), antes + 1)

    # Complete: abrir recusa um banco que não existe e não cria o arquivo.

    # Complete: um erro no meio do bloco desfaz também o que veio antes dele.

    # Complete: a conexão fica fechada depois do bloco, mesmo com erro.

@contextmanager
def conexao_banco(caminho=None):
    con = abrir(caminho or caminho_banco())
    try:

    finally:
