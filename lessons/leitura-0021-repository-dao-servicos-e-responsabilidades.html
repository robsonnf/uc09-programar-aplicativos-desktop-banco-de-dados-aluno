Repositório, serviço e quem liga: cada responsabilidade no seu lugar

O abrir_janela.py virou um depósito: tem o serviço de dados, a tradução de erros, o log, as caixas de diálogo e o começo do programa. Hoje cada responsabilidade ganha o seu arquivo. O repositório continua com o SQL; o serviço, em kits/dados.py, abre a conexão ou a transação de cada pedido, traduz os erros e registra o log; as caixas de diálogo vão para kits/dialogos.py; e o abrir_janela.py só liga as peças. O serviço passa a receber o repositório, a conexão e a transação, e por isso é testado sem MySQL.

A aula continua no projeto da A20. O comportamento não muda; só o lugar das coisas. Os testes do banco e de fluxo mudam uma linha: o import do DadosMySQL. Use dados fictícios.

Repositório, serviço e raiz de composição ↗

O repositório, kits/repositorio.py, sabe o SQL de cada operação: listar, adicionar, editar, importar. Cada função recebe uma conexão pronta e não abre, não confirma e não desfaz: por isso várias delas cabem numa transação só, como na importação da A19. É o que a literatura chama de repositório ou DAO, objeto de acesso a dados.

O serviço, kits/dados.py, atende um pedido da janela de cada vez: abre a conexão (para ler) ou a transação (para gravar), chama o repositório, traduz os erros que a janela sabe explicar (banco fora do ar, kit com itens) e registra no log o que precisa ficar registrado. Ele não sabe SQL nem janela.

A raiz de composição, abrir_janela.py, é o único lugar que conhece todas as peças de verdade: configura o log, cria o serviço, escolhe as caixas de diálogo e entrega tudo à janela. Trocar uma peça, por exemplo um serviço que lê de outro banco, é mudar uma linha ali.

Receber as dependências ↗

Até a A20, o DadosMySQL chamava conexao_banco e em_transacao direto, e as funções do repositório pelo nome. Para testá-lo, só com o MySQL ligado. Agora ele recebe as três peças no __init__: repo, conectar e transacao. Os valores padrão são os de verdade, então o abrir_janela.py e os testes do banco continuam chamando DadosMySQL() ou DadosMySQL(TESTE) como antes.

Nos testes do serviço, as peças são de mentira: um repositório que anota cada chamada e levanta o erro combinado, uma conexão que é só um nome, uma transação que anota que foi usada. É a mesma ideia do objeto de dados recebido pela janela (A14) e da visão recebida pelo controle (A20), agora um andar abaixo.

O que cada teste do serviço prova é a responsabilidade dele: que gravar passa pela transação (e assim herda a nova tentativa no deadlock), que o erro 2003 vira ConnectionError e o 1064 não, que KitComItens vira ValueError, e que a importação deixa uma linha no log.

"""O serviço DadosMySQL sem MySQL: repositório, conexão e transação de mentira, que anotam o que receberam."""
import contextlib
import unittest

import mysql.connector

from kits.dados import DadosMySQL


class KitComItens(Exception):
    pass


class RepositorioDeMentira:
    """Cada função anota (nome, conexão, argumentos) e devolve o combinado, ou levanta a falha combinada."""
    KitComItens = KitComItens

    def __init__(self):
        self.chamadas = []
        self.falhas = {}
        self.respostas = {}

    def __getattr__(self, nome):
        def funcao(con, *args):
            self.chamadas.append((nome, con, *args))
            if nome in self.falhas:
                raise self.falhas[nome]
            return self.respostas.get(nome)
        return funcao


class TestDados(unittest.TestCase):
    def setUp(self):
        self.repo = RepositorioDeMentira()
        self.aberturas = []

        @contextlib.contextmanager
        def conectar(config):
            self.aberturas.append(('conexão', config))
            yield 'con-leitura'

        def transacao(operacao, config):
            self.aberturas.append(('transação', config))
            return operacao('con-transação')

        self.dados = DadosMySQL({'database': 'kits_teste'}, repo=self.repo, conectar=conectar, transacao=transacao)

    def test_consulta_abre_uma_conexao_com_a_config_e_entrega_ao_repositorio(self):
        self.repo.respostas['listar_kits'] = [(1, 'Treinamento Redes')]
        self.assertEqual(self.dados.listar_kits(), [(1, 'Treinamento Redes')])
        self.assertEqual(self.aberturas, [('conexão', {'database': 'kits_teste'})])
        self.assertEqual(self.repo.chamadas, [('listar_kits', 'con-leitura')])

    def test_busca_passa_trecho_e_ordem_ao_repositorio(self):
        self.dados.listar_itens(1, 'cabo', 'quantidade', True)
        self.assertEqual(self.repo.chamadas, [('consultar_itens', 'con-leitura', 1, 'cabo', 'quantidade', True)])

    # Complete: remover(7) abre só a transação, com a config, e o repositório recebe ('remover_item', 'con-transação', 7).

    def test_mysql_fora_do_ar_vira_connection_error(self):
        self.repo.falhas['listar_kits'] = mysql.connector.Error(errno=2003, msg="Can't connect")
        with self.assertRaisesRegex(ConnectionError, r'Sem conexão com o MySQL \(erro 2003\)'):
            self.dados.listar_kits()

    # Complete: com mysql.connector.Error(errno=1064, msg='syntax') no criar_kit, o mesmo erro sobe, com errno 1064.

    # Complete: com KitComItens('Kit 1 ainda tem itens: remova os itens antes') no remover_kit, sobe ValueError com a mensagem.

    def test_importacao_aceita_e_recusada_vao_para_o_log(self):
        self.repo.respostas['importar_linhas'] = 2
        with self.assertLogs('kits.importacao', level='INFO') as log:
            self.assertEqual(self.dados.importar(['l1', 'l2'], 'itens.csv', 'a' * 64), 2)
            self.repo.falhas['importar_linhas'] = ValueError('linha 3: o kit Almoxarifado não existe; nada foi importado')
            with self.assertRaises(ValueError):
                self.dados.importar(['l1'], 'outra.csv', 'b' * 64)
        self.assertEqual(log.output, ['INFO:kits.importacao:importada itens.csv: 2 itens',
                                      'WARNING:kits.importacao:recusada outra.csv: linha 3: o kit Almoxarifado não existe; '
                                      'nada foi importado'])

    def test_defeito_na_importacao_sobe_sem_virar_recusa_no_log(self):
        self.repo.falhas['importar_linhas'] = KeyError('kit')
        with self.assertNoLogs('kits.importacao', level='WARNING'):
            with self.assertRaises(KeyError):
                self.dados.importar(['l1'], 'itens.csv', 'c' * 64)

"""Serviço de dados herdado, de outra equipe que também separou as camadas.

Para examinar: guarde o seu kits/dados.py (copie para dados_bom.py, fora da pasta kits), ponha este arquivo no
lugar dele, rode os testes e devolva o seu.
"""
import mysql.connector

from kits import repositorio
from kits.banco import conexao_banco, em_transacao


def protegido(operacao):
    try:
        return operacao()
    except mysql.connector.Error as erro:
        raise ConnectionError(f'Sem conexão com o MySQL (erro {erro.errno}). '
                              'Confira se o serviço está ligado e clique em Recarregar.') from erro


class DadosMySQL:
    def __init__(self, config=None, repo=repositorio, conectar=conexao_banco, transacao=em_transacao):
        self.config = config
        self._repo = repo
        self._conectar = conectar
        self._transacao = transacao

    def _consultar(self, funcao, *args):
        def operacao():
            with self._conectar(self.config) as con:
                return funcao(con, *args)
        return protegido(operacao)

    def _gravar(self, funcao, *args):
        return self._consultar(funcao, *args)

    def listar_kits(self):
        return self._consultar(self._repo.listar_kits)

    def listar_itens(self, kit_id, trecho='', ordem='nome', descendente=False):
        return self._consultar(self._repo.consultar_itens, kit_id, trecho, ordem, descendente)

    def resumo_kits(self):
        return self._consultar(self._repo.resumo_kits)

    def itens_abaixo(self, limite):
        return self._consultar(self._repo.itens_abaixo, limite)

    def criar_kit(self, nome):
        return self._gravar(self._repo.criar_kit, nome)

    def adicionar(self, kit_id, item):
        return self._gravar(self._repo.adicionar_item, kit_id, item)

    def editar(self, item_id, antes, depois):
        return self._gravar(self._repo.editar_item, item_id, antes, depois)

    def remover(self, item_id):
        return self._gravar(self._repo.remover_item, item_id)

    def remover_kit(self, kit_id):
        return self._gravar(self._repo.remover_kit, kit_id)

    def importar(self, linhas, arquivo, resumo):
        try:
            gravadas = self._gravar(self._repo.importar_linhas, linhas, arquivo, resumo)
        except (ValueError, ConnectionError) as erro:
            print('recusada', arquivo, erro)
            raise
        print('importada', arquivo, gravadas)
        return gravadas

from kits.repositorio import criar_kit
from kits.banco import conexao_banco


class DadosMySQL:
    def criar_kit(self, nome):
        with conexao_banco() as con:
            try:
                return criar_kit(con, nome)
            except Exception as erro:
                raise ValueError(str(erro))
Sem receber a conexão nem o repositório, este serviço só é testado com o MySQL ligado.

except Exception transforma qualquer defeito, até um erro de digitação no código, numa recusa que a janela mostra como normal.

conexao_banco não confirma nada: o kit criado nunca é gravado.
