Dois itens chamados Cabo ↗

A equipe de suporte precisa reabrir o aplicativo e recuperar os kits da A05. Hoje os kits vivem só na memória, e a equipe quer um banco que guarde os dados e recuse o que estiver errado.

Dois kits contêm um item chamado Cabo. Alguém pede para corrigir a quantidade do Cabo de um deles. Antes de qualquer alteração, a equipe precisa saber qual linha é a certa. Em dupla, proponha um critério para identificar o item sem depender do nome.

Da classe à tabela ↗

Uma tabela guarda linhas com as mesmas colunas. Cada linha precisa de uma chave primária: um valor que a identifica sozinho, mesmo quando o nome se repete.

Na A05, um Kit tinha uma lista self.itens. No banco não existe coluna do tipo lista: a relação muda de lado. Cada item guarda o identificador do seu kit em uma chave estrangeira. Um kit pode ter zero ou vários itens; cada item pertence a exatamente um kit. Isso é uma relação um-para-muitos (1:N).

Lista dentro do kit

Uma coluna de texto com ids separados por vírgula: o banco não confere se os itens existem, e consultar um item exige recortar texto.

kit(id, nome, itens)
1, 'Redes', '1,2'

Chave estrangeira no item

Cada item aponta para o seu kit. O banco confere o vínculo e a consulta usa junção.

item(id, kit_id, nome, quantidade)
1, 1, 'Cabo', 3

SQL essencial com um exemplo de biblioteca ↗

O exemplo usa autores e livros, um domínio diferente do seu, para você ver a estrutura sem copiar a resposta. A relação é a mesma: um autor tem vários livros.

Antes de UPDATE ou DELETE, rode um SELECT com o mesmo WHERE. Se aparecer mais de uma linha, ou a linha errada, pare: a alteração atingiria exatamente essas linhas.

Alterar direto

Sem conferir o alvo, o WHERE pelo título atinge todos os livros com esse título.

UPDATE livro SET paginas = 130 WHERE titulo = 'Primeiro';

Conferir, alterar, conferir

O SELECT mostra quem será atingido; o id garante uma linha só; o segundo SELECT mostra o efeito.

SELECT id, titulo, paginas FROM livro WHERE id = 1;
UPDATE livro SET paginas = 130 WHERE id = 1;
SELECT id, titulo, paginas FROM livro WHERE id = 1;
O PRAGMA vale por conexão

No SQLite as chaves estrangeiras começam desligadas em cada conexão nova. Cada execução de python -m sqlite3 é uma conexão nova: por isso todo script desta aula começa com PRAGMA foreign_keys = ON. Sem essa linha, um item com kit inexistente é aceito em silêncio.

Dica para raciocinar

A mensagem sozinha prova que a linha não foi gravada?

Uma ferramenta revisou o esquema de outra dupla e listou os achados abaixo. Julgue cada um: é problema real ou não?

CREATE TABLE kit (
  id INTEGER PRIMARY KEY,
  nome TEXT NOT NULL
);
CREATE TABLE item (
  id INTEGER PRIMARY KEY,
  kit_id INTEGER NOT NULL,
  nome TEXT NOT NULL,
  quantidade INTEGER NOT NULL CHECK (quantidade > 0)
);
item.kit_id não declara REFERENCES kit(id); um kit inexistente seria aceito mesmo com o PRAGMA ligado.

As tabelas têm nomes no singular (kit, item); deveriam estar no plural.

id INTEGER PRIMARY KEY sem AUTOINCREMENT faz o SQLite gerar ids repetidos.
